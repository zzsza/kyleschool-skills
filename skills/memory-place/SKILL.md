# 기억 속 장소 만들기

다시 가고 싶은 곳을 브라우저에서 걸어 다니는 3D 공간으로 만든다. 카일스쿨 Claude Code 2편(포르투 모루공원 노을)을 만든 순서 그대로다.

순서 : 묻기 → 기획안 확인 → 구현 → 고치기 → 함께 보기와 공유. **기획안을 사용자가 확인하기 전에는 구현하지 않는다.**

## 1. 묻기

한 번에 3~4개만 묻는다. 답이 짧으면 예를 들어 다시 묻는다.

- 어디인지, 언제 갔는지
- 무엇이 가장 기억에 남았는지(장면 하나. 예 : 잔디에 앉아 강 건너로 해 지는 것)
- 그때 찍은 사진이나 참고 자료가 있는지. 있으면 대화창에 넣어 달라고 한다
- 내 캐릭터 모습(머리, 안경, 옷 색)
- 혼자 볼지, 친구와 같이 볼지

사용자의 경험은 지어내지 않는다. 장소의 실제 배치(무엇이 어느 쪽에 있는지)는 검색으로 확인하고 출처를 기획안에 적는다. 사진이 있으면 검색보다 사진을 따른다.

## 2. 기획안

작업 폴더에 `plan.md`를 쓰고 사용자에게 보여 준다.

| 칸 | 내용 |
|---|---|
| 한 줄 | 어디서 무엇을 하는 공간인지 |
| 보이는 것 | 앞, 왼쪽, 오른쪽, 멀리. 사진이 있으면 사진 기준 |
| 할 수 있는 것 | 4개 이하(예 : 걷기, 앉기, 사진 찍기, 고양이 쓰다듬기) |
| 시간 흐름 | 시작 시각과 끝(예 : 해 질 녘 → 밤) |
| 내 캐릭터 | 모습과 후드 색 |
| 함께 보기 | 혼자 / 친구와 같이(Cloudflare) |
| 확인 못 한 것 | 검색으로 확인하지 못한 배치, 사용자에게 물어볼 것 |

사용자가 "좋아", "만들어 줘"라고 하면 구현으로 넘어간다. 고칠 줄을 말하면 그 줄만 고쳐서 다시 보여 준다.

## 3. 구현

`template/index.html`을 작업 폴더에 `index.html`로 복사하고, **`1. 설정(CONFIG)`과 `3. 장소 만들기(buildPlace)`만 고친다.** 내 캐릭터 모습(머리 모양 등)은 `4. 캐릭터`의 `makeAvatar`까지 고쳐도 된다. 옷 색은 `CONFIG.ownerHood`에 넣는다(내 파일로 열 때와 주인 링크로 들어올 때 적용되고, 다른 사람은 `friendHoods`에서 정해짐). 그 밖의 이동, 충돌, 시간 흐름, 앉기, 사진첩, 함께 보기 로직은 그대로 쓴다. 바꿔야 하면 무엇을 왜 바꾸는지 먼저 말한다.

| 시작 틀 구역 | 내용 |
|---|---|
| 1. 설정 | 이름, 시간대별 하늘 색, 해 지는 방향, 걷는 범위, 시작 위치, 앉는 곳, 랜덤 별명 단어 |
| 2. 장면 | 하늘, 해, 빛, 안개 |
| 3. 장소 만들기 | 땅, 물, 건물, 나무, 담. `tree()`, `house()`, `box()` 도우미 |
| 4. 캐릭터 | 머리가 큰 캐릭터, 걷기와 폴짝 |
| 5. 이동 | 키보드, 조작판, 바닥 누르기, 충돌, 뒤에서 따라가는 카메라 |
| 6. 시간 흐름 | 해가 지고 밤이 되면 창문이 켜짐. 앉아 있으면 3배 빠름 |
| 7. 앉기, 사진 | 앉는 곳 근처에서 앉기, 사진은 이 브라우저에만 저장 |
| 8. 함께 보기 | 같은 페이지를 연 사람끼리 위치, 자세, 별명 주고받기 |

좌표 규칙 : 처음 바라보는 쪽이 `-z`, 오른쪽이 `+x`, 땅은 `y = 0`, 1은 약 1m. 지나갈 수 없는 것은 `blockers.push({ x, z, r })`, 밤에 켜질 것은 `light(mesh)`로 등록한다. 땅 메시의 이름 `ground`는 유지한다(바닥 누르기에 씀). 카메라는 캐릭터 뒤 5.5m에서 따라오므로, 걷는 범위 뒤쪽 끝 가까이에 큰 물체를 두면 화면을 가린다. 먼 풍경은 실제 거리보다 가깝게 두고 기획안 '확인 못 한 것'에 적는다.

만든 뒤 브라우저로 열어 콘솔 에러가 없는지 보고, 화면을 캡처해 기획안과 나란히 보여 준다.

## 4. 고치기

사용자 말 한 번에 한 가지씩 고치고, 고칠 때마다 화면 캡처를 보여 준다.

- 말로 설명하기 어려우면 사진을 보여 달라고 한다. 구도는 사진 한 장이 말 열 줄보다 빠르다.
- 사용자가 쓰는 짧은 말을 아래 단어로 바꿔 이해한다. 사용자가 단어를 물으면 이 표로 알려 준다.

| 사용자가 하고 싶은 것 | 쓰는 말 |
|---|---|
| 캐릭터 따라가는 시점 | 3인칭 카메라 |
| 만화 같은 느낌 | 툰 셰이딩, 외곽선 |
| 해가 지고 밤이 되게 | 시간 흐름, 하늘 그라데이션, 조명 |
| 멀어질수록 흐리게 | 안개(fog) |
| 밤에 창문 불 | 발광(emissive) |
| 못 지나가게 | 충돌 처리 |
| 사람끼리 서로 보이게 | 멀티플레이 |
| 폰에서도 | 모바일 터치 조작 |
| 캐릭터를 더 정교하게 | Blender로 모델링해 glb로 내보내기 |

캐릭터를 Blender 모델로 바꿀 때는 Blender 파이썬(bpy) 스크립트로 모델을 만들고 glb로 내보낸 뒤, Three.js r128의 `GLTFLoader`로 불러온다. 못 불러오면 시작 틀의 도형 캐릭터를 쓰게 둔다. glb를 쓰면 파일을 더블클릭으로 열 수 없으므로 `python3 -m http.server`로 연다.

## 5. 함께 보기와 공유

함께 보기 로직은 시작 틀에 들어 있다. 어디에 올리느냐에 따라 들어올 수 있는 사람이 다르다.

| 올리는 곳 | 함께 보기 |
|---|---|
| 내 컴퓨터(파일 열기) | 혼자 보기 |
| claude.ai 아티팩트 | 공유받아 로그인한 사람끼리만 |
| Cloudflare | 링크를 받은 누구나 |

친구와 링크로 같이 보려면 `cloudflare-deploy` 스킬로 올린다("Cloudflare에 올려줘"). 주인 이름은 사용자 이름으로 정하고 `build`의 주인 이름 인자로 넣는다(`CONFIG.ownerName`은 이름을 못 받았을 때만 쓰임). 공유 링크만 `plan.md` 맨 위에 적는다.

## 하지 않는 것

- 다른 서비스의 화면, 이름, 기능을 그대로 따라 만들지 않는다. 계기로만 쓴다.
- 사용자가 말하지 않은 경험, 숫자를 지어내지 않는다.
- 확인하지 않은 배치를 "실제와 같다"고 말하지 않는다.
